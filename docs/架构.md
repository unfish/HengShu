# 衡枢架构

## 依赖方向

```text
CLI / Rust API / LSP
          |
词法器 -> 解析器 -> AST + 符号索引 -> 检查器 -> 编译器 -> 字节码验证器 -> VM
          |          |                         |                         |
          +----------+----> 结构化诊断 <-------+                         |
                     |                                                   |
                     +----------------> 解释器 <-------------------------+
                                            |
                             标准库 / 权限 / 并发 / 数据层
```

`main.rs` 只处理最终退出码，命令分派位于 `cli.rs`。Rust 嵌入方只通过 `api.rs` 进入，不直接依赖 AST、运行时值或 VM 内部结构。

大模块按状态所有权继续细分：`cli/automation.rs` 只负责排程与独立包自动化命令适配；`automation/history.rs` 独占 SQLite schema、触发预约和运行提交；`vm/machine.rs` 独占调用帧与指令循环；`desktop/model.rs` 保存平台无关控件映射和状态机；`delivery/layout.rs` 把报告 IR 转成 `printpdf` 操作；`delivery_template/{docx,xlsx}.rs` 分别拥有两类 OOXML 替换；`ingest/xlsx.rs` 拥有工作簿关系、隐藏/合并结构和日期系统。父模块只保留公开类型、跨格式分派和适配入口。

解释器的环境生命周期、预算、调用绑定、对象访问和模块加载位于 `src/runtime/` 子模块。标准库把进程、网络、路径和纯工具能力放在 `src/stdlib/` 子模块；这些模块只接收完成操作所需的上下文。统计和线性代数纯算法位于 `src/analysis/` 子模块，不依赖解释器状态。

所有执行路径共享解析、检查、调用契约、权限和资源限制。解释器与 VM 的结果由差分测试约束；独立打包只执行经过验证的字节码，并在构建时固化权限。

词法、解析、静态检查和运行时错误统一携带`SourceSpan`，范围使用从 1 开始的 Unicode 标量行列；CLI 渲染中文消息，Rust API 直接暴露结构化范围，LSP 在协议边界转换为从 0 开始的 UTF-16 位置。解释器与 VM 从当前执行语句或指令的源码映射产生运行时范围，不解析错误消息恢复行号。错误消息只写原因文本，任何层都不得把`第 N 行发生错误：`一类定位前缀写进消息，定位只在渲染时按范围输出一次。

一次失败的完整身份由`diagnostic::DiagnosticReport`表示：类别、范围、消息、调用栈、参数定义范围和原因链。进程内与跨进程共用这一个结构——`RuntimeError::report`与`HengshuError::report`产生它，CLI 与独立包在`HENGSHU_DIAGNOSTIC_FILE`指向文件时把同一份 JSON 写出，因此工具链和门禁无需从渲染文本反解。失败退出码只由`api::FAILURE_EXIT_CODE`定义。解释器与 VM 的执行边界无论成败都返回解释器本身，失败前产生的输出与失败原因因此同时可观察，并通过`HengshuError::output`暴露给嵌入方。

解析器在 AST 的名称表达式和所有可绑定声明上保留精确范围，并在构造`Program`时建立带父级关系的词法作用域符号索引。索引为每个绑定分配稳定的文档内标识，定义跳转和重命名按绑定标识工作，不按文本全局搜索；重命名还会拒绝同作用域重复和内层捕获。符号索引属于编译器内部表示，不是 0.9 公共 Rust API。

打包器遍历完整 AST 收集导入。主程序和每个模块分别保存“源码导入文本到包内模块 ID”的映射；模块 ID 使用包内确定性序号，VM 用它缓存和检测循环，同时继续使用源码名称绑定变量与显示诊断。运行时模块环境还分配独立模块身份，用于结构名义类型和内部方法访问控制。

独立包把载荷追加在可执行文件之后，尾部依次是标记、载荷摘要、载荷长度和同一个标记。载荷定位只依赖这一结构，不依赖摘要是否匹配；摘要比较因此是唯一的完整性判定点，被改写的载荷报出“内嵌程序校验失败”，不会退化成普通命令行工具。

## 边界原则

- 上层可以依赖下层，底层算法不能依赖 CLI。
- 权限检查发生在实际 I/O 前，重定向和规范化后必须重新检查。
- 用户输入错误通过结构化公共错误或中文 CLI 消息返回。
- 不可信字节码必须先检查大小、反序列化完整性和控制流有效性。
- 工程清单固定的权限是上限，调用方只能求交收紧；独立包的无密钥摘要只检测损坏，不是防篡改边界。
- 阻塞操作使用总执行预算与局部超时的较小值，并支持取消。
- 语言求值（源码解释、测试运行和任务线程）在 `resource::execution_thread` 提供的大栈线程上执行，宿主栈不参与资源边界判定。
