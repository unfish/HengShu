# 衡枢 0.9 API 稳定性与兼容承诺

本文定义衡枢 0.9 系列的源码、字节码、命令行和标准库兼容规则。

## 稳定范围

- Rust 嵌入入口 `check_source`、`run_source`、`compile_source`、`run_compiled`和`format_source`，以及`CompiledProgram::run`、`HengshuError`、`ErrorKind`、`SourcePosition`、`SourceSpan` 和 `PermissionSet`；`HengshuError::line()`、`column()`、`span()`、`category()`、`stack()`、`cause()`与`definition_span()`属于稳定的只读诊断接口，详细范围见 [嵌入 API](嵌入API.md)。
- `.代码` 文件中的公开关键字、语句结构和中文类型名称。
- `衡枢 新建、运行、检查、打包、验证包、存证、验证凭证、复算、排程、历史、测试、格式化、文档、基准、添加、移除、更新、缓存、审计、发布、版本、帮助` 命令及机器可读基线列出的参数。
- `docs/标准库索引.md` 和 `skills/hengshu/api.json` 列出的公开模块、功能、属性和动作。
- 打包文件的载荷版本诊断和损坏校验。字节码仅承诺由同一主版本编译器读取，不承诺第三方直接修改二进制编码。

AST、语义索引、解释器环境、运行时值、字节码内部结构和 VM 是内部实现，不属于 0.9 稳定承诺。`CompiledProgram`只承诺通过公开方法验证、执行和序列化，不公开内部指令。

## 兼容规则

1. 同一主版本内不得删除公开语法或改变既有程序的正常结果。
2. 新增可选参数、模块、错误字段和诊断建议属于兼容变更。
3. 修复安全漏洞、拒绝未定义行为或纠正明显错误时，可以改变错误结果，但必须写入发布说明。
4. 标准 SQL、HTTP 方法、URL、JSON、正则和 MIME 类型继续使用外部标准，不建立翻译别名。
5. 中文类型契约保持主谓结构，不引入 `变量名: 类型` 或 `类型 变量名`。

## 弃用周期

公开 API 弃用必须经历至少一个次版本周期：先在文档和运行时诊断中标记弃用并给出替代写法，再在下一个主版本删除。安全原因需要立即禁用时，发布说明必须说明影响和迁移方法。

## 版本规则

- 补丁版本用于兼容修复、性能改进和文档更新。
- 次版本用于向后兼容的新语法、新标准库和新工具能力。
- 主版本允许不兼容变更，并必须提供迁移指南。

机器可读 API 基线位于 `skills/hengshu/api.json`。发布前 CI 必须校验测试数量、格式、Clippy、覆盖率、三平台构建和源码包。
