# 衡枢维护者手册

## 职责

维护者负责版本方向、兼容性、安全响应、代码评审和发布。解析器/检查器、解释器/VM、标准库 I/O、数据分析和工具链分别视为独立所有权区域；跨区域变更必须说明每个区域的验证结果。

项目应逐步培养至少三位能够独立评审的维护者。任何人不能仅因提交了实现就自行批准涉及权限、字节码、发布签名或兼容性承诺的重大变更。

## 决策

- 缺陷修复和内部重构通过普通 PR 处理。
- 新语法、公开 API、权限能力、字节码变更和重大依赖必须先提交设计提案供评审。
- 安全修复可以先在私密分支处理，披露后补充设计记录。
- 无法达成一致时，优先保持兼容和较小攻击面，并记录暂缓理由。

## 评审清单

- 行为是否由测试证明，而非只由实现推断。
- 解释器、VM 和独立打包是否保持一致。
- 用户输入是否可能触发 panic、无界分配、无限等待或权限逃逸。
- 是否改变公开语法、标准库、错误类别、CLI 或字节码。
- 文档、机器可读 API 基线和迁移说明是否同步。

## 发布

发布者按 `docs/发布清单.md` 操作。发布失败时不得复用已经公开的版本号；签名密钥、平台构建凭据和安全报告权限必须最小化分配。
