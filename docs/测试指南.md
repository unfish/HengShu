# 衡枢测试指南

衡枢发布前同时验证语言语义、标准库、CLI、字节码和独立程序。测试必须使用临时目录或 `tests/data` 中的只读数据，不能依赖 Python、Node.js、外部数据库或公共网络。

## 快速反馈与完整验收

日常开发先运行快速门禁；它包含全部库单元测试和不反复构建、启动独立包的集成测试：

```bash
bash scripts/test-fast.sh
```

三路径差分、CLI 子进程、独立打包和大型语言矩阵集中在慢速门禁。共享语义、打包或自动化执行链变更应在定向测试通过后运行一次，发布验收必须运行：

```bash
bash scripts/test-slow.sh
```

脚本中的测试目标清单是显式的。新增集成测试必须按是否重复启动子进程、构建独立包或生成大型矩阵归入其中一个脚本；CI 会分别执行两组，不能通过遗漏目标缩短门禁。

完整发布门禁还包括：

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
bash scripts/test-fast.sh
bash scripts/test-slow.sh
cargo test --doc
cargo test --all-targets -- --list
cargo build --release
cargo package --allow-dirty --no-verify
cargo audit --ignore RUSTSEC-2026-0235 --ignore RUSTSEC-2026-0194 --ignore RUSTSEC-2026-0195
cargo deny check
```

测试清单必须不少于 350 个独立名称。CI 在 Linux、macOS、Windows 执行快速门禁，在 Linux 执行慢速门禁和 `cargo llvm-cov --all-targets --fail-under-lines 70`，并在三平台分别构建。

模糊测试使用 nightly 编译器（本地命令写作 `cargo +nightly fuzz`），稳定工具链只负责常规构建和测试。

release 尺寸与冷启动基线使用 `scripts/release-baseline.sh`。

## 三路径发布门禁

涉及语言语义的回归必须用同一份源码依次验证源码解释器、内存字节码 VM 和独立打包程序。三条路径逐项比较退出码、标准输出和结构化诊断；失败用例同样比较失败前已经打印的每一行，因为“失败前做了什么”也是语义。差分前先执行解析与静态检查，不能用无效 AST 掩盖编译器缺陷。

结构化诊断由 `DiagnosticReport` 表示，包含错误类别、精确源码范围、消息、调用栈、参数定义范围和原因链。独立包路径通过环境变量 `HENGSHU_DIAGNOSTIC_FILE` 读取子进程写出的同一份 JSON，不允许从渲染后的中文文本反解类别或行号，也不允许伪造列号。被信号终止的子进程直接判为门禁失败。

`tests/common/mod.rs` 提供唯一入口：`assert_three_paths`、`assert_three_paths_with_modules`、`assert_three_paths_output`、`assert_three_paths_output_with_modules`、`assert_three_paths_failure` 和 `assert_three_paths_failure_with_modules`。新增语义回归必须走这些函数，不得在测试内自行拼装单路径执行。

断言必须可能失败。禁止提交结构上恒真的断言（例如比较同一个 `Rc` 的自反相等、用远大于实际的上界约束元素个数、或断言空列表长度为零）；改为比较独立构造的等价值、精确的元素个数与取值，或程序真正可观察的副作用。

控制流、绑定、类型、调用、值、模块和并发用例应按组合矩阵组织，并覆盖成功和失败路径。深递归、深层相等、循环容器、复杂 `最终` 和模块递归等可能触及宿主栈的用例必须在子进程中执行，断言正常返回语言错误，而不是 signal、abort、退出码 134 或超时。

项目权限中的 `最大调用深度`、`最大值嵌套深度` 和 `最大模块深度` 必须在解释器、VM、模块和打包载荷中使用同一预算；测试同时覆盖 CLI 参数、`衡枢.toml` 清单和打包后删除源码的执行。深度回归必须至少有一项使用默认预算而不传 `--最大调用深度`，否则调小的预算会掩盖宿主栈容量不足的缺陷。

## 使用衡枢编写测试

```bash
target/release/衡枢 测试 tests/单元测试.代码
target/release/衡枢 测试 tests
target/release/衡枢 测试 . --筛选 边界
target/release/衡枢 测试 tests --列出
target/release/衡枢 测试 tests --遇错即停
```

自动化流水线默认把“没有发现测试”视为错误；只有明确允许空测试的通用模板才使用`--允许空测试`。测试发现按路径排序并递归执行，跳过`target`、`.git`和`.衡枢缓存`。筛选在执行前完成，失败命令返回非零退出码。

语言测试至少覆盖正常值、边界值、错误输入和清理路径。共享夹具在顶层定义，由`测试准备`初始化；每项测试通过`每项测试前`恢复所需状态。测试之间不得依赖执行顺序。资源型夹具必须在`每项测试后`或`测试收尾`释放，并验证正文失败时清理仍会执行。

## 关键失败用例

- SQLite 批量插入中发生唯一约束冲突，整个事务必须回滚为零行。
- HTTP 取消文件已存在时，客户端必须在连接前返回“网络请求已取消”。
- 字节码常量索引、函数索引、跳转目标、异常区间、源码映射和栈深度必须由验证器检查。
- 调用帧覆盖递归和默认参数；闭包覆盖多层捕获与多次创建的独立环境。
- 异常表覆盖跨调用帧展开、捕获后重抛，以及 `最终` 在成功、异常和返回路径上的执行。
- 独立打包验收必须在删除 `.代码` 源文件后运行闭包和异常示例，载荷中不得包含 AST 语句。
- 依赖源码被篡改时，审计和模块解析必须失败；源码消失但校验缓存存在时必须离线解析。
- `甲 -> 乙 -> 甲` 模块图必须报告完整循环路径。
- `内部 定义` 的模块绑定不能从其他模块访问，`任务组：...结束` 必须等待任务且在块错误时取消任务。
- 日志轮换目标不能删除或重命名时，错误必须返回调用方，不能静默丢日志。
- 打包后移走 `.代码` 文件，在 `/` 目录和空 `PATH` 下仍应执行成功。

## 测试数据

- `tests/data/销售数据.csv`：地区、产品和销售指标，用于分组和统计。
- `tests/data/数组数据.csv`：数值列，用于分块聚合和内存路径。
- `tests/data/工邦邦商品列表.html`：两条商品卡片，覆盖中文、货期、正常价格和私用字体价格。
- `tests/data/工邦邦货期响应.json`：公开货期接口的固定响应，用于字段映射。
- HTTP 使用测试进程内的 `127.0.0.1` 临时端口，测试 multipart 请求体和延迟响应读取。
- SQLite 使用 `:memory:`，文件数据库测试使用临时目录。
- Parquet、XLSX、日志和发布归档由测试临时生成并在测试结束后自动清理。

## 手工独立程序验收

```bash
target/release/衡枢 检查 examples/语法/01_基础值与控制流.代码
target/release/衡枢 运行 examples/语法/01_基础值与控制流.代码
target/release/衡枢 打包 examples/语法/01_基础值与控制流.代码 -o /tmp/基础值与控制流
cd /
env -i PATH= /tmp/现代语言能力
```

最后一步执行前应先把原始 `.代码` 文件移出测试目录，用于证明产物不读取源码。

需要本机 Chrome 的动态分页测试默认忽略，手工执行：

```bash
cargo test chrome_paginates_a_local_dynamic_fixture --lib -- --ignored
```

该测试只访问进程内 `127.0.0.1` 页面。公网工邦邦、豆瓣和 Books to Scrape 示例不进入自动测试，发布前按用户手册命令检查前三页 CSV；外部站点返回限流、验证页或结构变化时记录实际状态，不绕过验证机制。
