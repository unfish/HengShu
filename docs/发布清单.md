# 发布清单

1. 运行格式、严格 Clippy、全部测试、文档测试、覆盖率和 fuzz smoke。
2. 在 Linux、macOS、Windows 验证 Release 构建和独立打包。
3. 检查版本号、兼容性说明、标准库索引和机器可读 API 基线。
4. 生成源码包、平台产物、SHA-256 校验文件和 SBOM。
5. 在干净环境删除源码后运行打包产物，并验证权限固化和可复现归档。
6. 创建签名标签和发布说明，列出安全修复、废弃项、已知问题和升级步骤。
7. 发布后重新下载产物验证校验值，并观察 CI、Issue 和安全报告渠道。

## 平台打包脚本

在项目根目录执行：

```text
scripts/package-platform.sh <程序.代码或项目目录> <工具名> <输出目录>
```

macOS 生成 arm64/x86_64 对应的 CLI、签名 `.app`、`SHA256SUMS`、`DEPENDENCIES.cargo-metadata.json` 和 `BUILD-MANIFEST`。Linux 生成 CLI、AppDir，并在安装 `appimagetool` 时额外生成 AppImage；Windows 使用 PowerShell：

```powershell
scripts/package-platform.ps1 -Source <程序.代码或项目目录> -Tool <工具名> -Output <输出目录>
```

脚本会调用 `衡枢 验证包` 检查 CLI/GUI 载荷类型、载荷版本、模块和工具 schema。当前 macOS 验收覆盖 arm64 构建、`.app` 签名/Info.plist、CLI 删除源码运行；Windows/Linux 由发布机器手工执行并记录结果。

## 签名边界

脚本在 macOS 上只做 ad-hoc 签名，仅用于本机启动验证，不构成对外可信签名。正式发布必须在发布机器上补齐：macOS 用 Apple Developer ID 签名并公证，Windows 产物用 Authenticode 签名，Linux 产物提供分发渠道要求的签名或校验方式。这些步骤完成前，发布说明和校验文件不得声称产物已签名。

macOS 正式签名与公证：

```text
HENGSHU_SIGN_IDENTITY="Developer ID Application: <团队名> (<TEAMID>)" \
  scripts/package-platform.sh <程序.代码或项目目录> <工具名> <输出目录>
xcrun notarytool submit <输出目录>/<工具名>.app --keychain-profile <配置名> --wait
xcrun stapler staple <输出目录>/<工具名>.app
```

设置 `HENGSHU_SIGN_IDENTITY` 时脚本会启用 hardened runtime 和安全时间戳；公证与装订仍需发布机器上的 App Store Connect 凭据。

## Linux 容器验收

没有 Linux 实机时，可在容器里验收 Linux CLI：

```text
scripts/verify-linux-container.sh
```

脚本使用官方 `rust:slim` 镜像执行 Release 构建、追加载荷、删除源码后运行和 `衡枢 验证包`，容器架构即宿主架构。

GUI 侧用另一个脚本在容器里做软件渲染验收：

```text
scripts/verify-linux-gui-container.sh
```

它安装 X11、mesa、Xvfb、xdotool、x11-utils 和 Noto CJK 字体，用 `LIBGL_ALWAYS_SOFTWARE=1` 打包 GUI 产物、跑 `验证包`，再在 Xvfb 里启动窗口并确认窗口真的创建后截图。容器 locale 无法把 `UTF8_STRING` 窗口名转成本地编码，因此不能用 `xdotool --name` 匹配中文标题；脚本改为先等任意可见窗口出现，再用 `xprop _NET_WM_NAME` 断言标题是清单里的中文标题，并用 `xwininfo` 记录窗口尺寸。`HENGSHU_GUI_SCREEN`（默认 `640x480x24`）和 `WINIT_X11_SCALE_FACTOR`（默认 2）可用来模拟窄窗口与高 DPI。AppImage 打包和真实桌面缩放仍需真实图形会话验收。

### Windows CLI 容器预验收

```text
scripts/verify-windows-container.sh
```

脚本在 `--platform linux/amd64` 的 `rust:slim` 容器里安装 mingw-w64 与 Wine，为 `x86_64-pc-windows-gnu` 交叉编译 `衡枢`，然后在 Wine 下执行「打包 → 删除源码 → 运行 → `验证包`」，并用 `file` 记录产物确实是 `PE32+ … x86-64` 控制台程序。Wine 对非 ASCII 可执行名支持不稳，脚本把主程序复制成 ASCII 名再调用。这只是预验收：Wine 不等于真实 Windows，GUI `.exe` 的双击运行、系统缩放、字体和 SmartScreen 行为仍必须在 Windows 实机上验收。
