# 把每天重复的表格工作，写成一门看得懂的中文语言

如果你做过财务、运营、销售或数据分析，大概都遇到过这样的工作：

打开几张表，删掉几行无效数据，统一日期和金额格式，按照地区或产品汇总，再把结果贴进报告。月底、周末、季度末各来一遍。流程并不复杂，真正麻烦的是它总在重复，而且每次都可能多一步、少一步，最后很难说清楚结果是怎么来的。

很多人会用 Excel，也有人会写 Python 或 SQL。它们都很好，但不一定适合每一个工作场景。Excel 依赖人的操作顺序，脚本往往需要学习另一套英文语法和运行环境。于是我们做了衡枢：一门面向财务核算、报表处理和数据分析的中文编程语言。

它不是把英文关键字逐个翻译成中文，也不是让程序“听懂人话”后凭感觉执行。衡枢仍然是一门有明确语法、可以检查、可以测试、可以打包的编程语言，只是它试着用更接近中文工作表达的方式来写程序。

## 先看一个小例子

下面这段程序读取销售表，算出平均销售额、分位数，并按地区汇总：

```text
引入 表格处理
引入 统计分析

定义 表 为 表格处理 读取表格("销售数据.csv")
定义 销售额 为 统计分析 数组(表 的 销售额)

输出("平均销售额", 销售额 平均值())
输出("销售额分位数", 销售额 分位数([0.25, 0.5, 0.75]))
输出("地区汇总", 表 分组统计(["地区"], 聚合 为 "求和"))
```

这段代码没有隐藏的点击步骤。输入文件是什么、取了哪一列、做了什么统计、最后输出什么，都写在程序里。下个月换一份数据，通常只需要换输入文件，而不是重新回忆一遍操作顺序。

衡枢的语法有几个很直接的约定：第一次声明用“定义”，修改已有值用“为”；代码块用“结束”收尾；列表从 1 开始编号；对象的从属关系用“的”表达，比如“订单 的 金额”。这些选择不一定适合所有程序，但和表格、单据、业务规则的阅读习惯比较接近。

## 它解决的不是“不会算”，而是“每次都要重新算”

衡枢更适合那些规则已经比较明确、但需要反复执行的工作：

- 批量读取 CSV、XLSX、Parquet 文件，筛选、排序、去重、连接和分组统计；
- 计算均值、分位数、相关性、回归、预测和安全库存；
- 把结果写回 CSV、XLSX，或生成 HTML、SVG、PDF 报告；
- 做对账，保留匹配状态、差异字段和规则版本；
- 在写入 Word 或 Excel 模板时只改声明过的单元格和占位符，不重新排版原文件；
- 连接 SQLite、HTTP、TCP/UDP 和本地进程，处理文件流和大数据流；
- 把程序打包成一个不依赖原始源码的独立程序，交给同事或客户直接运行。

项目里准备了几条完整的角色配方。财务示例会做流水和台账对账，生成差异清单并填充报告；HR 示例会连接员工和薪资数据，先处理敏感字段再生成工资条；销售示例会做排名、区域透视和周报；老师、医生、公务员等场景也各有一条从数据到结果的流程。

## 财务数据最怕的，是“看起来差不多”

在财务工作里，少一分钱有时比多一段代码更严重。因此衡枢没有把所有数字都当作普通的二进制浮点数，金额默认使用高精度十进制表示。币种、小数位、舍入方式、含税或未税口径，需要在程序中明确写出。

同样的原则也用于统计和预测：缺失值怎么处理、异常值是否保留、验证数据能不能参与训练、预测区间代表什么，都应该有清楚的规则，而不是在某个函数里悄悄改变数据。结果不仅给出一个数字，也会尽量保留字段说明、单位、敏感标签和来源信息。

## 出错时，要知道错在哪里

自动化最让人不放心的，往往不是成功，而是失败后没人知道发生了什么。

衡枢的解析错误、类型错误、权限错误和运行时错误都会带源码位置。程序先输出了三行，第四行除零失败，那么这三行输出不会被吞掉；嵌入 API 还能拿到结构化的错误类别、源码范围、调用栈、原因链和此前输出，而不需要从一段中文错误文本里猜测发生了什么。

同一份程序可以走源码解释器、字节码虚拟机，也可以打包成独立程序。三条路径共用解析后的语义、权限和资源限制，目标是让“在我的电脑上能跑”不再成为唯一的验收标准。

## 权限不是一句提醒，而是一道边界

文件、网络、环境变量、子进程和输出目录都可以配置权限。程序要访问一个路径、发送一次请求或启动一个进程，必须先通过对应的授权；路径规范化、重定向之后还会再次检查。敏感数据外发时，还需要同时声明允许的端点和敏感类别。

这意味着，程序里写了“发送邮件”并不等于它就能把数据发出去。权限和资源预算是程序的一部分，调用深度、集合大小、缓冲区、输出字节和执行时间都有上限。对普通用户来说，这些机制不必每天手动管理；对需要把程序放进 CI、定时任务或客户环境的人来说，它们可以减少很多意外。

## AI 可以帮忙，但不负责替你算数

衡枢包含实验性的人工智能模块，但它不是一个内置联网的“万能分析按钮”。默认情况下不联网，也不会自动调用模型。用户明确选择在线、记录、重放或离线模式后，AI 才参与资料抽取、结论草拟或报告文字整理。

真正的统计量、检验、回归和图表数据仍然由确定性的分析代码产生。模型输出会作为普通数据处理，不会被当成衡枢源码或系统命令执行。这样做的好处很朴素：AI 可以帮忙读材料、组织语言，但不能悄悄改掉计算结果。

## 从一份 `.代码` 文件开始

衡枢的源码扩展名是 `.代码`。安装 Rust stable 后，可以直接构建项目并运行示例：

```bash
cargo build --release
target/release/衡枢 检查 examples/销售分析.代码
target/release/衡枢 运行 examples/销售分析.代码
```

程序确认无误后，可以打包：

```bash
target/release/衡枢 打包 examples/高级统计.代码 -o ./高级统计程序
./高级统计程序
```

打包后的程序不再读取原始 `.代码` 文件，适合交付给不需要接触源码的使用者。项目还提供用户手册、完整语法参考、标准库索引、Rust 嵌入 API、VS Code 扩展和可运行示例，方便从一段小程序逐步试起来。

## 这不是终点，而是一种取舍

衡枢不会替代 Excel，也不会要求所有人都改用中文编程。它更像是给一类重复、明确、需要留痕的工作多一个选择：把散落在操作步骤、聊天记录和个人经验里的规则，写成一份可以检查、可以复用、可以交付的程序。

如果你正在处理报表、对账、批量文件、经营分析，或者只是想看看一门中文编程语言到底能做到什么，欢迎从 `examples/` 目录里的小程序开始。项目采用 MIT License 开源，代码、文档和问题反馈都在同一个仓库里，欢迎试用，也欢迎直接指出不合理的地方。

衡枢希望解决的事情并不复杂：让程序更接近业务人员的表达，让结果经得起复算，也让下一次重复工作不必从头再来。
