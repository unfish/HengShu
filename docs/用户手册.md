# 衡枢用户手册

衡枢是一门面向财务、运营和数据分析的中文编程语言。源码使用 `.代码` 后缀，编译器和运行时由 Rust 实现，不依赖 Python 或 Node.js。

## 快速开始

安装 Rust stable 后构建：

```bash
cargo build --release
target/release/衡枢 检查 examples/销售分析.代码
target/release/衡枢 运行 examples/销售分析.代码
target/release/衡枢 打包 examples/高级统计.代码 -o ./高级统计程序
./高级统计程序
```

新建工程：

```bash
衡枢 新建 销售项目
衡枢 测试 销售项目
衡枢 格式化 销售项目
衡枢 文档 销售项目
```

一个完整程序：

```text
引入 统计分析
定义 销售额 为 统计分析 数组([120, 150, 90, 180])
输出("平均销售额", 销售额 平均值())
输出("中位数", 销售额 中位数())
```

## 中文语法原则

衡枢使用结构化中文，不把英文类型语法直接翻译成中文。

```text
定义 金额 为 128.50，类型限定为 数字
要求 金额 的类型是 数字
要求 金额 >= 0，否则说明 "金额不能为负数"
```

不要写 `金额: 数字` 或 `数字 金额`。类型通常由值推断，只有业务边界需要说明时才写类型契约。

代码块用 `结束` 闭合。属性使用“的”，动作直接跟在对象后面：

```text
输出(客户 的 名称)
客户 修改地址("上海")
```

SQL、HTTP 方法、URL、JSON、正则表达式和 MIME 类型保持原样：

```text
引入 数据库
定义 连接 为 数据库 打开SQLite("财务.db")
定义 记录 为 连接 查询("SELECT * FROM sales WHERE region = ?", ["华东"])
```

## 基础类型

数字统一使用高精度 Decimal；逻辑值是 `是` 和 `否`；缺失值是 `空`。

```text
定义 数量 为 3
定义 单价 为 12.50
定义 商品 为 "键盘"
定义 已付款 为 是
定义 备注 为 空
输出(数量 * 单价)
```

列表下标从 1 开始：

```text
定义 客户 为 {"姓名": "李明", "等级": "黄金"}
输出(客户 的 姓名)
定义 数据 为 [1, 2, 3, 4]
输出(长度(数据))
定义 唯一值 为 集合([1, 1, 2, 2])
```

## 参数化输出

`参数化输出`使用一个模板字符串，并从当前作用域自动读取占位符中的变量，不需要再次写“变量 为 变量”。业务报告和面向用户的文本优先使用`参数化输出`；`输出`用于直接输出值和调试信息。

```text
定义 订单数 为 1234567
定义 销售额 为 1234567.8
参数化输出("订单数：{订单数:千分位,0位小数}，销售额：{销售额:千分位,2位小数}")
```

输出：

```text
订单数：1,234,567，销售额：1,234,567.80
```

占位符格式为`{变量}`或`{变量:格式}`。目前支持`千分位`、`N位小数`（`N`为 0 至 28），多个选项用中文或英文逗号分隔；`{{`和`}}`分别输出字面量花括号。变量可以来自全局作用域、功能参数或功能内部定义。引用未定义变量、对非数字使用数字格式、格式选项错误以及括号不配对都会返回中文运行错误。

金额保留币种、小数位、舍入规则和审计记录：

```text
引入 财务
定义 金额 为 财务 金额(100.00, "CNY", 小数位 为 2)
定义 税额 为 金额 计算税额(13)
输出(税额)
```

不同币种不能直接相加，必须先换算。

## 控制流和功能

```text
定义功能 计算等级（分数）：
    如果 分数 >= 90：
        返回 "优秀"
    否则，如果 分数 >= 60：
        返回 "合格"
    否则：
        返回 "需要补考"
    结束
结束

定义 成绩 为 [95, 72, 48]
遍历 成绩，记作 分数：
    输出(计算等级(分数))
结束
```

闭包可以保存为值：

```text
定义 起点 为 10
定义 增加 为 定义功能（数值）为 数值 + 起点
输出(增加(5))
```

## 错误处理

```text
尝试：
    定义 结果 为 1 / 0
捕获 异常：
    输出(异常 的 类别, 异常 的 信息, 异常 的 行号)
最终：
    输出("清理完成")
结束
```

主动失败使用 `抛出`，输入约束使用 `要求`。

## 文件和数据交换

```text
引入 文件系统
定义 文本 为 文件系统 读取文本("输入.txt")
文件系统 写入文本("输出.txt", 文本)
定义 每行 为 文件系统 逐行读取("大文件.csv")
```

支持 UTF-8、UTF-16、GB18030、Base64、十六进制、JSON、JSON Lines、TOML 和 gzip。

## 表格和统计

```text
引入 表格处理
引入 统计分析
定义 表 为 表格处理 读取表格("销售数据.csv")
定义 销售额 为 统计分析 数组(表 的 销售额)
输出(销售额 平均值())
输出(销售额 分位数([0.25, 0.5, 0.75]))
```

已按目标指标排序的大型结果文件可以限制读取行数，避免为 Top-N 报告物化完整文件：`表格处理 读取表格("商品.csv", 最大行数 为 20)`。最大行数仍受项目集合资源限制约束。

多表工作簿、多层表头和脏数据可以用命名选项声明，不写这些选项时读取行为与旧版完全一致：

```text
定义 二月 为 表格处理 读取表格("多表.xlsx", 工作表 为 "二月")
定义 明细 为 表格处理 读取表格("多表.xlsx", 工作表序号 为 2, 表头行数 为 2)
定义 严 为 表格处理 读取表格("脏账.csv", 模式 为 "严格")
```

`工作表序号` 从 1 开始；`表头行数` 大于 1 时按列把多行表头用下划线拼接；`模式 为 "严格"` 时需要修复的单元格、歧义日期和无缓存公式一律报错，`"宽松"` 则标准化后继续读取。

写出时目标以 `.json` 结尾写 JSON 行数组，`.xlsx` 写工作簿，其余写 CSV；`单位schema` 选项把表级与列级的单位、口径和敏感标签写成显式 schema，供下游核对：

```text
表格处理 写入表格(结果, "结果.json", 单位schema 为 "结果.schema.json")
```

统计分析包含描述统计、相关矩阵、t 检验、方差分析、卡方检验、曼-惠特尼 U、置信区间、逻辑回归、时间序列分解、预测和线性规划。

数值数组还支持稳健统计和序列统计：

```text
定义 销量 为 统计分析 数组([10, 11, 9, 10, 100])
输出(销量 极差())
输出(销量 四分位距())
输出(销量 中位绝对偏差())
输出(销量 平均绝对偏差())
输出(销量 变异系数())
输出(销量 偏度())
输出(销量 峰度())
输出(销量 自相关(滞后 为 1))
输出(销量 移动平均(窗口 为 3))
```

异常值分析支持`四分位距`、`Z分数`和`修正Z分数`。检测结果包含上下界、异常索引、异常值、保留值、缩尾值和布尔掩码：

```text
定义 异常 为 统计分析 异常值检测(销量, 方法 为 "四分位距", 阈值 为 1.5)
定义 排异结果 为 统计分析 排除异常值(销量)
定义 缩尾结果 为 统计分析 缩尾异常值(销量)
```

需求预测会先在原始时间轴上按顺序切分训练集和验证集，再只用训练段拟合异常值边界。验证段只能使用训练边界变换，不能参与阈值估计。预测流程不允许用“排除”删除周期，只能选择“不处理”或“缩尾”，从而保持训练、验证和季节位置不变。模型同时比较朴素、移动平均、简单指数平滑、霍尔特趋势和可选季节朴素模型，以 WAPE 为主、RMSE 为辅选择。零实际值不会导致 MAPE、sMAPE 或 WAPE 产生非有限结果：

```text
定义 预测 为 统计分析 需求预测(
    [10, 11, 12, 13, 14, 15, 16, 17],
    步数 为 4,
    验证期 为 4,
    移动窗口 为 4,
    季节周期 为 4,
    异常处理 为 "缩尾"
)
输出(预测 的 最佳模型, 预测 的 预测质量, 预测 的 模型评估)
输出(预测 的 模型参数, 预测 的 区间置信度, 预测 的 区间方法)
输出(统计分析 预测准确度([10, 12], [9, 13]))
```

预测结果的`字段说明`以表格列出各字段口径。当前`预测下限`和`预测上限`是根据留出验证 RMSE 构造的名义 95% 正态近似区间，不是模型参数置信区间；区间方法和名义置信度会分别写入`区间方法`与`区间置信度`，便于报告显式披露。

人工智能能力目前是实验性且默认不联网（可切换在线/记录）。请在源码或打包程序运行目录创建固定名称的 `环境.配置` 文件，以 `HENGSHU_AI_API_KEY=...` 等键提供 AI 参数；`人工智能 请求`支持`离线`、`模拟`和项目内 JSON `重放`；默认信任项目可直接使用配置的网络和环境变量，显式受限项目才按权限清单限制。`人工智能 分析结论`会发送版本化的任务类型、用户目标、受众、统计上下文、允许引用路径和固定输出结构，返回带`引用字段`、`事实`、`模型解释`和`建议行动`的文本结果。图片与 PDF 输入会检查文件类型、大小和 Base64 膨胀；模型输出永远作为值处理，不会执行为源码或命令。

`人工智能 生成报告(分析结果, 报告要求)` 返回经过 HTML 转义的草稿、引用字段和可交给`报告 导出`的标准报告对象。可通过`HTML模板`传入包含`{{标题}}`、`{{结论}}`、`{{引用}}`和`{{警告}}`的可编辑模板，并用`主题`和`章节顺序`调整标准报告。模板受输出字节、节点和外部资源检查；不通过时自动回退到标准草稿。离线、模拟和重放结果标记为完全可复现；在线结果标记为不可复现，且不会覆盖原始统计结果。

需要从合同、邮件或客服文本中提取业务字段时，使用`人工智能 提取结构化(原文, 字段定义)`。字段定义支持三种写法：只写字段名（默认文本）、记录简写（`{"金额": "数字"}`）和详细记录（`{"名称": "金额", "类型": "数字", "允许空": 是, "说明": "含税金额"}`）。类型支持`文本`、`数字`、`整数`、`逻辑`、`日期`、`日期时间`及对应列表类型。程序会将字段定义组装为根为`数据`数组的严格 JSON Schema，并在本地再次校验类型、字段集合和空值。

返回值仍是普通记录：`数据`字段已经是表格，可直接调用`筛选`、`分组统计`、`选择列`，或传给`表格处理 写入表格`保存为 CSV/XLSX。`行数`和`字段`分别提供结果计数与实际列名；模型只返回文本或 JSON 时，用户代码不需要手动解析 JSON。

示例见 `examples/AI结构化提取.代码`：

```text
定义 结果 为 人工智能 提取结构化(原文, [
    {"名称": "订单号", "类型": "文本"},
    {"名称": "金额", "类型": "数字"},
    {"名称": "已付款", "类型": "逻辑"}
], 模式 为 "在线")
定义 订单表 为 结果 的 数据
表格处理 写入表格(订单表, "订单.csv")
```

图表支持`参考线`、`区间下限`、`区间上限`和`注释`参数，用于把目标值、预测区间和业务说明直接叠加到 Plotters 图表。

纯统计报告示例见 `examples/纯统计报告.代码`，统计结果加 AI 叙事示例见 `examples/统计与AI报告.代码`。前者不调用模型，后者使用模拟模式，便于在无网络环境验证两条路径。

`需求稳定性`同时给出有销量率、变异系数、连续销量周期、趋势以及 ADI/CV² 分类。需求类型分为平稳需求、波动需求、间歇需求和块状需求。

安全库存使用需求标准差、服务水平、提前期及提前期标准差计算。库存下限等于补货点；库存上限覆盖提前期加审查周期。只有提供`当前库存`或`在途库存`时才会计算`建议补货量`：

```text
定义 库存 为 统计分析 安全库存(
    [10, 11, 12, 13, 14, 15],
    预测需求 为 预测 的 预测,
    服务水平 为 0.95,
    提前期 为 2,
    提前期标准差 为 0.5,
    审查周期 为 1,
    当前库存 为 20,
    在途库存 为 5
)
输出(库存 的 安全库存, 库存 的 库存下限, 库存 的 库存上限)
```

流式多维汇总的日期维度支持`周`转换，结果使用周一日期。批量需求预测会补齐缺失周的零销量，筛选稳定热销商品，并输出所有候选模型的验证指标、最佳模型、未来预测、安全库存和库存上下限：

```text
定义 商品预测 为 统计分析 批量需求预测(
    商品周销量,
    商品列 为 ["SkuNumber", "ProductId"],
    周期列 为 "周",
    销量列 为 "订购数量",
    最低周期数 为 20,
    最低有销量率 为 0.8,
    最大变异系数 为 1.0,
    最低平均销量 为 5,
    只保留可靠预测 为 是,
    最大验证WAPE 为 50
)
```

周预测应只使用完整自然周，避免首尾残缺周污染回测。异常缩尾默认只改变建模序列，原始周销量和异常周期数仍保留；促销、断货和大客户订单应结合业务事件复核，不能仅凭统计规则永久删除。

## 网络、数据库和进程

网络调用保留标准方法名：

```text
引入 网络
定义 响应 为 网络 请求("POST", "https://api.example.com/sales", JSON 为 {"金额": 100})
输出(响应 的 状态码, 响应 转JSON())
```

表单、代理和重试：

```text
定义 响应 为 网络 请求("POST", "https://example.com/login",
    表单 为 {"用户名": "用户", "密码": "密码"},
    最长等待 为 持续时间("30秒"),
    重试次数 为 2,
    再次尝试前等待 为 持续时间("2秒"),
    代理 为 "http://127.0.0.1:8080")
```

文件上传使用 multipart，字段值是待上传文件路径；`取消文件` 是协作取消约定，程序或外部监控创建该文件后，请求会在发送前和重试间检查并停止：

```text
定义 响应 为 网络 请求("POST", "https://example.com/import",
    文件上传 为 {"数据": "销售.csv"}, 取消文件 为 "停止请求")
```

响应的 `设置Cookie` 属性是完整的 `Set-Cookie` 列表，同名响应头不会折叠。衡枢不会自动把 Cookie 发送到其他域。

静态 HTML 使用标准 CSS 选择器提取：

```text
引入 网页
定义 记录 为 网页 按字段采集(HTML, ".product", {
    "名称": ".name",
    "编码": {"选择器": "a", "属性": "data-code"}
})
```

动态网页可由本机 Chrome 或 Chromium 加载和翻页。字段配置支持 `选择器`、`属性`、`HTML` 和 `拒绝私用字符`；后者用于拒绝无法可靠解释的网页私用字体字符。`内容加载完成标志` 要求每个记录容器的动态子区域出现后再采集。`网页 逐页采集` 使用 `最多采集页数`、`翻页后至少等待`、`翻页后最多等待` 和 `页面最长等待` 表达运行约束，例如 `持续时间("1.2秒")`，不会要求使用者换算毫秒。它不会绕过登录、验证码、私有加密或反自动化限制。

网页采集接口支持 CSS 选择器和动态分页；可将采集结果交给 `examples/语法/03_表格统计预测.代码` 的分析流程：

```bash
衡枢 运行 采集.代码 --允许 '网络:*' --允许 子进程 --最长执行时间 15分钟
```

正式工程应根据实际请求收紧到具体主机，避免使用网络通配授权。

网络采集不在发布示例中绑定第三方站点，避免站点改版、限流或验证页导致入门流程失效。请在自己的 `采集.代码` 中声明目标主机并按最小权限运行。

SQLite 始终使用标准 SQL 和参数化查询，禁止拼接用户输入。

## 并发和流

```text
引入 并发
定义功能 加倍（数值）：
    返回 数值 * 2
结束
定义 结果 为 并发 并行映射([1, 2, 3], 加倍, 工作者 为 2)
输出(结果)
```

任务可用 `最长等待 为 持续时间("30秒")` 等待，也可以取消；通道容量提供背压。文件、HTTP 响应和数据库查询都可以转换为流。

结构化任务组在离开业务步骤前统一等待，出现错误时会取消尚未完成的任务；块内变量不会泄漏到外部。通道可以直接转成流：

```text
定义 组 为 并发 任务组()
定义 任务 为 并发 启动(工作)
并发 加入任务组(组, 任务)
定义 结果 为 并发 结束任务组(组, 取消 为 否)
定义 通道 为 并发 通道(100)
定义 数据流 为 并发 通道转流(通道)
```

也可以使用词法作用域任务组，省去手工收集任务：

```text
任务组：
    定义 任务 为 并发 启动(工作)
结束
```

需要在一次扫描中同时完成多个业务维度的汇总时，使用流式多维汇总。维度支持原值、日期、月份、季度和年份转换；指标支持计数、非空计数、去重计数、求和、绝对值求和、乘积求和、平均值、极值、时差平均以及差值、比率、百分比等派生计算：

```text
引入 表格处理

定义 方案 为 [
    {"名称": "月份", "维度": [{"列": "下单时间", "名称": "月份", "转换": "月份"}]},
    {"名称": "地区", "维度": ["省份", "城市"], "指标": ["订单数", "销售额", "成本额", "毛利额", "毛利率"]}
]
定义 指标 为 [
    {"名称": "订单数", "聚合": "去重计数", "列": "订单号"},
    {"名称": "销售额", "聚合": "求和", "列": "金额", "去重列": "订单明细号"},
    {"名称": "成本额", "聚合": "乘积求和", "列": ["成本价", "数量"]},
    {"名称": "毛利额", "计算": "差值", "左": "销售额", "右": "成本额"},
    {"名称": "毛利率", "计算": "百分比", "分子": "毛利额", "分母": "销售额"}
]
定义 汇总 为 表格处理 流式多维汇总("大文件.csv", 方案, 指标)
输出(汇总 的 月份)
```

第四个参数可提供基于 ISO 日期或日期时间文本的左闭右开区间过滤，例如 `{"列": "下单时间", "开始": "2026-01-01", "结束": "2026-07-01"}`。过滤在聚合前逐行执行，不会物化中间表。

`求和`、`绝对值求和`、`乘积求和`、`平均值` 和 `时差平均` 可配置 `去重列`。同一分组内使用相同去重列的指标共享去重状态，适合避免订单明细因拆包、分批发货而重复计算销售额、数量和成本。

分组方案可用 `指标` 选择本方案实际需要的指标；未配置时计算全部指标。派生指标必须同时选择其依赖项。按方案选择指标既能减少精确去重内存，也能明确事实粒度：订单金额适用于下单月份、商品、客户和收货区域等订单粒度维度；承运商、发货月份和包裹状态等发货粒度维度通常只应计算发货量、时效和签收指标。同一 `去重列` 在每个分组内独立去重，因此跨分组变化的维度不能直接把金额小计解释为可加总事实。

HTTP 的 `转流()` 不会预先复制正文；每次收集或遍历只读取一个块。SQLite 查询仍以表格返回，`流式查询()` 会按统一流接口暴露查询结果。

`流式查询()` 每次取下一项时只向 SQLite 请求一行；只有显式调用 `收集()` 才会把结果物化为列表。

## 对账

`对账 比对(左表, 右表, 规则)` 接收两个表格或两组记录，按规则给出逐行结果表；`对账 统计(结果表)` 按状态计数。

```text
引入 对账
定义 规则 为 {
    "版本": "月度对账v1",
    "编号字段": "凭证号",
    "精确键": ["凭证号"],
    "比较字段": ["金额", "日期"],
    "金额字段": ["金额"],
    "绝对容差": 0.01,
    "日期窗口": {"日期": 2}
}
定义 结果 为 对账 比对(流水, 台账, 规则)
定义 统计 为 对账 统计(结果)
```

结果表的列是 `状态`、`左编号`、`右编号`、`评分`、`规则版本` 和 `差异`。`状态` 取 `已匹配`、`仅左侧`、`仅右侧`、`字段不一致`、`重复键`、`疑似匹配`、`多义`、`未判定` 或 `规则错误`；`差异` 是记录列表，每项含 `字段`、`左值`、`右值` 和 `差额`，差额按“左减右”计算。`编号字段` 缺省时按行序编号。金额字段用 `绝对容差` 和 `相对容差` 判断一致，日期字段用 `日期窗口` 给出允许的天数偏移，`模糊字段` 与 `模糊阈值` 控制疑似匹配，候选边超过 `候选上限` 直接报资源错误而不是退化成部分结果。规则版本随每行返回，便于人工复核时确认口径。

## 权限和资源限制

衡枢默认信任用户自己运行的代码，网络、环境变量和子进程不需要逐项授权。CI、教学平台或嵌入宿主可以显式收紧权限：

```bash
衡枢 运行 分析.代码 --允许 文件:./数据 --允许 网络:api.example.com
衡枢 运行 任务.代码 --允许 子进程 --最长执行时间 30秒 --最大调用深度 1024 --最大输出字节 1048576 --最大缓冲字节 67108864
```

未配置时，单次缓冲输入默认限制为 64 MiB，集合物化为 100 万项，程序输出为 16 MiB，功能调用深度为 1024，值嵌套深度为 256，模块递归加载深度为 64，语法嵌套深度为 1024，源码文件为 16 MiB。超过这些规模的数据应使用对应的流式读取接口；工程可在 `衡枢.toml` 的权限段设置 `最长执行时间 = "30秒"`、`最大调用深度`、`最大值嵌套深度`、`最大模块深度`、`最大缓冲字节`、`最大集合项数` 和 `最大输出字节`。语法嵌套深度在 `检查`、`打包` 和 `运行` 上一致生效，过深的嵌套表达式返回编译错误而不是崩溃。通道容量上限为 65536 项、并行映射工作者上限为 64 个，这两项是绝对上限，工程配置和命令行只能在其之内收紧。

列表、记录、集合和结构不能直接或间接包含自身。集合扩容会在写入前检查上限；范围、流收集、表格连接、数据库参数、报告和统计分析使用同一个项目上限。通道、任务参数、任务返回和并行映射使用同一跨任务值编解码器，集合往返仍是集合；不能恢复完整语义的结构实例和宿主资源会在发送或启动前明确拒绝。

命令行解释执行允许`输入()`读取终端。Rust 嵌入 API 默认禁用交互式标准输入，嵌入方必须显式设置`RunOptions.allow_interactive_input = true`；限时输入复用进程级工作线程，不会为每次超时遗留一个线程。

工程可在 `衡枢.toml` 通过 `限制能力 = true` 主动启用受限权限。受限清单是上限，命令行只能进一步收紧；未启用限制的用户项目默认信任运行，不维护逐次授权或项目级信任记录。无论是否受限，超时、取消、输入/输出和集合预算都继续生效。

打包时权限写入载荷，独立程序运行时忽略命令行权限参数，因此运行中不能扩大。载荷尾部的 SHA-256 摘要没有密钥，只用于发现截断和意外损坏，不构成防篡改边界：能改写可执行文件的人可以同时改写权限并重算摘要。需要抗篡改时应由分发渠道对可执行文件签名。

程序里用列方法声明敏感列：`表 设置列敏感("身份证", "身份")` 支持 `身份`、`联系`、`财务`、`医疗`、`教育` 和任意自定义类别名，`表 列敏感("身份证")` 返回 `类别`、`已脱敏` 和 `已假名化`，掩码或假名化处理之后用 `标记列脱敏` / `标记列假名` 记录结果。标签跟随列经过 `选择列`、`排序`、`去重`、`连接`、`透视` 和通道/任务传递；只有所有带标签的列都已脱敏或假名化，整表才按已处理放行。

脱敏和假名化本身由 `隐私` 模块提供：

```text
引入 隐私
输出(隐私 掩码("110101199001011234"))
输出(隐私 掩码("13800001111", 保留后 为 4))
输出(隐私 假名化("张三", "盐值"))
输出(隐私 分箱(37.4, 5))
```

`掩码` 默认整串替换为 `*`，`保留前` 和 `保留后` 只能选一个；`假名化` 用密钥派生稳定摘要，同一密钥下同一输入结果一致，换密钥结果不同；`分箱` 返回所属区间的下界。这三个函数不需要权限，也不会修改列标签，处理完仍要用 `标记列脱敏` 或 `标记列假名` 记录状态。

带敏感标签的数据外发要同时通过端点授权和类别授权，两者都在 `衡枢.toml` 的权限段声明：

```toml
["权限"]
"允许敏感类别" = ["Financial"]
"允许端点" = ["LocalFile", "Pdf", "EvidenceView"]
```

`允许端点` 的取值是 `LocalFile`（CSV/XLSX/DOCX 等本地文件与模板替换输出）、`Pdf`（PDF 报告与 Artifact）、`Stdout`（标准输出）、`Log`（日志）、`SmtpBody`、`SmtpAttachment`、`Webhook` 和 `EvidenceView`（凭证中的参数与输出明细）。为空表示不额外限制端点，旧工程行为不变。

判定只作用于带敏感标签且未脱敏、未假名化的数据：表格的标签是表级标签与各列标签的并集，任何一列敏感就要授权整表外发。端点未列入允许集合时报“端点未授权”，端点允许但类别未列入 `允许敏感类别` 时报类别未授权。`衡枢 验证凭证` 在缺少 `EvidenceView` 授权时只打印计数，参数值和输出行会替换为占位符。

本地依赖可使用`校验固定 = "SHA-256摘要"`固定内容。该字段只检测依赖内容是否变化，不验证发布者身份，也不是数字签名。清单只接受`校验固定`；未知字段（包括旧`签名`字段）会作为配置错误拒绝。

## 中文自动化测试

测试可以写在项目的 `tests` 目录，也可以放在任意普通目录或单个 `.代码` 文件中：

```text
定义 基准数据 为 [10, 20, 30]

测试准备：
    断言不为空（基准数据）
结束

每项测试前：
    断言相等（长度（基准数据），3）
结束

测试 "平均值正确"：
    断言接近（平均值（基准数据），20，允许误差 为 0.000001）
结束

测试 "错误路径正确"：
    断言会失败（
        定义功能（）：
            抛出 "数据不能为空"
        结束，
        信息包含 为 "不能为空"
    ）
结束

每项测试后：
    断言相等（长度（基准数据），3）
结束

测试收尾：
    断言不为空（基准数据）
结束
```

四个准备与收尾块都只能写在文件顶层，同类块在一个文件中最多一个。普通顶层声明先执行，随后执行一次`测试准备`；每项测试依次执行`每项测试前`、测试正文和`每项测试后`；全部测试结束后执行一次`测试收尾`。逐项测试使用独立的内存状态，一项测试对列表、记录、集合、表格或变量的修改不会污染下一项。`每项测试后`和`测试收尾`在前面的步骤失败时仍会执行。

可用断言包括：`断言`、`断言相等`、`断言不相等`、`断言包含`、`断言为空`、`断言不为空`、`断言接近`和`断言会失败`。值比较断言可以在最后增加中文说明；`断言接近`使用`允许误差`；`断言会失败`接收一个无参功能，并可用`信息包含`核对错误内容。

```bash
衡枢 测试 tests/财务测试.代码
衡枢 测试 tests/统计
衡枢 测试 销售项目
衡枢 测试 tests --筛选 边界
衡枢 测试 tests --列出
衡枢 测试 tests --遇错即停
衡枢 测试 可能为空的目录 --允许空测试
```

单文件只执行该文件；普通目录递归执行其中全部 `.代码` 文件；带 `衡枢.toml` 的项目根执行其 `tests` 目录。文件按路径排序，`target`、`.git`和`.衡枢缓存`会被跳过。筛选在任何测试正文执行前生效。失败或默认情况下没有发现测试时，命令返回非零退出码，便于直接接入 CI。

## 工程和发布

```bash
衡枢 添加 数据工具 --路径 ../数据工具 --版本 ^0.1
衡枢 更新
衡枢 缓存 数据工具
衡枢 审计 项目
衡枢 基准 项目/src/主程序.代码 --次数 20
衡枢 基准 项目/src/主程序.代码 --次数 20 --最大平均毫秒 500
衡枢 发布 项目 -o ./发布目录
```

`衡枢 更新`写入的`衡枢.lock`使用相对于项目根的路径。本地依赖位于项目外时会保存为`../数据工具`一类规范化相对路径，因此项目与同级依赖目录整体复制或移动后仍可解析。锁文件只接受相对路径；绝对路径会被拒绝，必须重新执行`衡枢 更新`生成当前格式。缓存、审计、运行和打包都使用同一套锁路径解析规则。

发布归档包含独立程序和 `SHA256SUMS`。

## 排程与文件夹监视

在 `衡枢.toml` 里按工具名声明自动化触发，日历只支持每周和每月两种周期：

```toml
["自动化"."日报"]
"时区" = "Asia/Shanghai"
"触发" = { "日历" = { "表达式" = "每周一 08:00" } }
"重试次数" = 1
"错过策略" = "补跑一次"
"重叠策略" = "跳过"
```

监视文件夹时改写触发部分。Linux/macOS/Windows 分别使用 inotify/FSEvents/ReadDirectoryChangesW 产生候选路径；网络盘或事件丢失场景可以显式启用轮询补偿。所有候选都要在大小和修改时间稳定、路径与扩展名匹配后才会入队：

```toml
"触发" = { "文件夹" = { "根目录" = "待处理", "扩展名" = "xlsx" } }
```

触发时间按声明的 IANA 时区解释。三平台任务每分钟唤醒固化了自动化声明的 CLI 包，由包内规则判断是否到点，因此不受宿主本地时区影响。夏令时前跳导致声明的本地时间当天不存在时，触发推迟到当天第一个存在的时刻；回拨导致同一本地时间出现两次时，只取更早的一次。机器关机或休眠错过的触发按 `错过策略` 处理。

排程命令操作当前用户级任务：Windows 写入任务计划 XML 并调用 `schtasks.exe`，macOS 写入 `~/Library/LaunchAgents` 的 plist 并调用 `launchctl`，Linux 写入 `~/.config/systemd/user` 的 service/timer 并调用 `systemctl --user`。安装和卸载需要子进程权限以及对任务描述文件所在目录的文件权限。

```bash
衡枢 打包 项目 --工具 日报 -o ./日报
衡枢 排程 安装 --工具 日报 --程序 ./日报
衡枢 排程 查询 --工具 日报
衡枢 排程 卸载 --工具 日报
衡枢 排程 触发 --工具 日报
衡枢 历史 --数量 20
```

安装时自动化声明、权限和工具 schema 一并固化到载荷版本 14。系统任务通过独立包内部入口运行，不依赖源码或 `衡枢.toml`，并把状态、诊断和通知结果写入产物旁的 `.衡枢运行历史.db`。`衡枢 排程 触发` 可用于手动触发一次任务，`衡枢 历史` 可以查询或导出记录。SMTP 正式连接和 MIME 编码由 `lettre`/rustls 实现；明文 SMTP 只允许本机测试夹具。

## 工具参数与权限

打包后的工具用 `--参数 名称=值` 传参，值按声明的类型解析：`整数`、`数字`/`小数`、`文本`，`逻辑` 同时接受 `是`/`否` 和 `true`/`false`。类型不符、缺少必填参数或传入未声明的参数都在运行前失败，并指出参数名。

```bash
./日报 --参数 数量=3 --参数 启用=是 --参数 名称=甲
```

工具段的 `"权限"` 只能收紧项目权限，不能扩大，因此需要写文件的工具要先在项目段声明：

```toml
["权限"]
"文件" = ["."]
```

独立程序把相对路径锚定到产物自身所在目录，因此从任何当前目录运行结果都落在产物旁边。安装目录只读时写出会失败，错误会指出操作和目标路径。

## 秘密参数

工具参数声明 `type_name = "秘密"`（或显式 `secret = true`）后：GUI 用密码控件显示，运行提交后立即清空该输入框，不做本地保存；命令行接收到的秘密值会登记到当前进程，之后渲染的中文错误、`HENGSHU_DIAGNOSTIC_FILE` 结构化诊断、运行历史记录和崩溃输出都会把该值替换成 `<秘密已隐藏>`。少于 4 个字符的值不登记，避免把普通文本大面积涂黑。

## 查看过程报告

`--观察` 打开执行观察后，过程报告有三种查看方式：

```text
衡枢 运行 主程序.代码 --观察 快照 --过程报告 过程报告.json
衡枢 运行 主程序.代码 --观察 快照 --过程报告 过程报告.html
```

- 命令行：目标以 `.html` 或 `.htm` 结尾时写出不含脚本的静态查看器，其余写出 JSON。
- 图形界面：结果页分「输出」「交付物」「过程」「诊断」四个标签页（标签上带条数），正文是可选中复制的只读文本框，随窗口高度自适应；过程页每行标注源码行号，并说明事件按字节码指令记录，因此一行代码通常对应多条指令。可保存 JSON 或 HTML 到输出目录。
- VS Code：安装 `editors/vscode` 扩展后，打开 `过程报告.json` 会得到字段说明、补全和格式校验。

## 人审签清单

生成或修改的程序在交付前由人复核，逐项对照可验证的证据：

- 需求与声明：输入表的列、金额列的单位与口径、敏感列、允许的权限与端点都已写明，与 `衡枢.toml` 一致。
- 源码范围：`衡枢 检查 程序.代码` 通过；复核意见引用具体文件与行号，而不是描述性说法。
- 测试：`衡枢 测试` 通过，正常值、边界值和预期错误路径各有独立测试。
- 权限：清单里没有超出实际需要的文件根、网络主机、环境变量或子进程授权。
- 凭证与复算：`衡枢 存证` 产出凭证，`衡枢 验证凭证` 显示输入与外部依赖计数，`衡枢 复算` 在提供原始数据后重算一致；加 `--字节码` 时先核对凭证记录的字节码摘要再在 VM 上重放；图形界面结果页的「保存凭证」把本次运行写成凭证，秘密参数只记名字不记值；存在未录制外部依赖时不得声称完整复算。
- 过程：`--过程报告` 的 Notebook 中“读取 → 清洗 → 对账 → 模板替换 → 输出”各步存在且顺序合理。
- 溯源：关键结果能追到来源节点（对账行、模板替换、报告 PDF、脱敏、单位转换），敏感明细在无授权时被遮挡。

## 关于 AI 生成

工具链不内置联网 AI 服务，也不在运行时调用任何模型；`skills/hengshu` 只是给外部助手的写作约束。AI 生成的代码与手写代码走同一套检查、权限、预算和测试，不存在绕过路径。

## 故障排查

- “没有访问文件路径”：通过 `--允许 文件:路径` 或工程权限清单授权。
- “没有访问网络主机”：授权精确主机或受控子域。
- “变量已经定义过”：修改变量时直接写 `变量 为 新值`。
- “对象没有属性”：确认属性使用“的”，动作使用功能名。
- 打包后找不到模块：运行 `衡枢 更新`，再检查 `衡枢.lock` 和 `衡枢 审计`。
- 编译器错误：使用 `衡枢 检查 文件.代码` 获取源码行号。
- 需要让脚本或 CI 判断失败原因：`衡枢 运行`与打包后的程序在任何失败上都以退出码 1 结束，中文错误文本写到标准错误，失败之前已经打印的内容仍留在标准输出。把环境变量 `HENGSHU_DIAGNOSTIC_FILE` 设为一个文件路径，同一次失败还会把结构化 JSON 诊断写入该文件，包含错误类别、源码范围、消息、调用栈、参数定义范围和原因链，无需从中文文本反解。
