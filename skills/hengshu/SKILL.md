# 衡枢代码生成 Skill

## 工作顺序

1. 先确认输入、输出、文件路径、网络主机和数据规模。
2. 生成前写下声明：每张表的列名与含义、金额列的单位与口径、要打敏感标签的列、需要的权限（文件/网络/环境/子进程）与允许端点、以及计划写的测试。缺一项先补齐再写代码。
3. 选择标准库模块并使用中文对象语序。
4. 默认使用类型推断；只有边界约束才写“类型限定为”和“要求”。
5. SQL、HTTP 方法、URL、JSON、正则表达式和 MIME 类型保持标准原文。
6. 为文件、网络、环境变量、子进程和数据库文件声明最小权限；敏感数据外发同时声明 `允许敏感类别` 和 `允许端点`。
7. 生成后依次执行“衡枢 格式化”“衡枢 检查”“衡枢 测试”“衡枢 运行”，需要发布时再执行“衡枢 打包”。
8. 不要使用变量名冒号类型、类型前置变量名、Python、Node.js 或未声明的第三方运行时。

## 中文语法硬约束

正确：

~~~text
定义 金额 为 128.50，类型限定为 数字
要求 金额 >= 0，否则说明 "金额不能为负数"
定义 表 为 表格处理 读取表格("销售.csv")
定义 结果 为 连接 查询("SELECT * FROM sales WHERE amount > ?", [100])
~~~

错误：

~~~text
金额: 数字
数字 金额
SELECT * FROM sales WHERE amount > 100
~~~

代码块必须用“结束”闭合。列表下标从 1 开始。变量先“定义”，修改时使用“变量 为 新值”。功能、分支和循环只使用以下现行语法：

~~~text
定义功能 计算（数值）：
    如果 数值 > 0：
        返回 数值
    否则，如果 数值 = 0：
        返回 0
    否则：
        返回 绝对值(数值)
    结束
结束

遍历 数据，记作 项：
    输出(项)
结束

当 次数 < 10 时重复：
    次数 为 次数 + 1
结束
~~~

不要生成旧写法 `功能`、`否则如果`、`只要...就一直进行` 或 `...中的每个...都进行`。

需要带业务说明和数字格式的输出时，优先使用 `参数化输出`，占位符直接引用当前作用域变量：

~~~text
定义 订单数 为 1234567
定义 销售额 为 1234567.8
参数化输出("订单数：{订单数:千分位,0位小数}，销售额：{销售额:千分位,2位小数}")
~~~

测试使用中文生命周期和断言。共享状态先在顶层定义，再在准备块中赋值；不要让测试依赖执行顺序：

~~~text
定义 基准数据 为 [10，20，30]

测试准备：
    断言不为空（基准数据）
结束

测试 "平均值正确"：
    断言接近（平均值（基准数据），20，允许误差 为 0.000001）
结束

测试 "错误路径正确"：
    断言会失败（
        定义功能（）：
            抛出 "数据不能为空"
        结束，
        信息包含 为 "不能为空"
    ）
结束
~~~

可使用`测试准备`、`每项测试前`、`每项测试后`和`测试收尾`。可用断言是`断言`、`断言相等`、`断言不相等`、`断言包含`、`断言为空`、`断言不为空`、`断言接近`和`断言会失败`。

## 选择模板

- CSV/XLSX：引入 表格处理，读取后交给 统计分析。
- 脏 XLSX：明确工作表、表头行数和严格/宽松模式；合并表头、隐藏行列、1900/1904 日期和原始坐标由摄入层处理，不要自行拆 ZIP/XML。
- 大文件：使用 文件系统 逐行读取 或 统计分析 读取CSV分块。
- SQLite：使用参数化标准 SQL 和事务。
- HTTP：使用标准 GET、POST 等方法；为域名声明网络权限。
- 等待时间：使用 `持续时间("1.2秒")`、`持续时间("3分钟")` 等带单位表达；命名参数使用 `最长等待`，不要生成毫秒换算参数。
- 静态网页：先用 `网络 请求` 获取 `文本正文`，再用 `网页 按字段采集` 和 CSS 选择器整理记录；HTTP 会按响应声明解码 UTF-8、GB18030 等字符集。
- 动态网页：使用 `网页 逐页采集`，以 `最多采集页数`、`翻页后至少等待`、`翻页后最多等待`、`页面最长等待` 和 `内容加载完成标志` 控制过程；需要网络与子进程权限。
- 财务：使用 财务 金额，明确币种和小数位，禁止不同币种直接运算。
- 单位/口径：使用 `单位 创建`、`单位 换算`、`单位 税转换` 和 `单位 舍入`；跨币种或跨口径必须显式给出有限正汇率/税率，维度不兼容必须失败。
- 隐私：先用 `设置列敏感` 标注，再实际执行 `隐私 掩码`、`隐私 假名化` 或 `隐私 分箱`，最后用 `标记列脱敏`/`标记列假名` 记录状态；聚合不会自动洗白敏感标签。
- 对账：使用 `对账 比对`/`对账 统计`，显式声明精确键、金额容差、日期窗口和候选上限；Unicode 兼容字符由运行库规范化，不自行实现模糊距离。
- 并发：只把数字、文本、列表和记录等可移植值传给 并发 启动；通过通道设置容量。
- 报告：先生成统计结果，再调用图表或报告模块写入授权目录。PDF 表格会渲染为网格、SVG 图表会真实嵌入，数字显示最多两位小数；不要输出 Markdown 表格或 SVG 文件名代替内容。
- 原格式交付：DOCX/XLSX 使用 `交付 模板替换`；基础 Word 转 PDF 使用 `交付 Word转PDF`。宏、OLE、外部关系、路径穿越和超预算 OOXML 会在写出前拒绝。
- 凭证复算：用 `衡枢 存证` 记录输入、结构指纹、Artifact、诊断和资源，再用 `衡枢 复算 --输入根` 比较；时间、随机数、网络和秘密参数只能得到指纹验证，不能声称完整复算。
- 自动化：在 `衡枢.toml` 的 `["自动化"."工具名"]` 声明日历/文件夹触发、IANA 时区、并发、队列、超时、重叠、SMTP/Webhook。它不是 `.代码` 关键字；先打包载荷版本 14 的 CLI，再用 `衡枢 排程` 安装。文件事件由原生 watcher 候选、稳定检测和有界队列共同决定。
- 预测：按原始时间轴留出验证期；异常阈值只能由训练段拟合，预测流程不得使用“排除”删除周期。
- 库存：先用`需求稳定性`筛选稳定商品，再用`需求预测`比较候选模型，最后以`安全库存`计算补货点和库存上下限。

## 生成检查清单

- [ ] 文件后缀是 .代码
- [ ] 每个条件、循环、定义功能、结构、尝试和匹配都有“结束”
- [ ] 使用“否则，如果”“遍历...记作”“当...时重复”现行语法
- [ ] 没有冒号式类型声明
- [ ] 外部标准没有被翻译
- [ ] 输入有“要求”契约
- [ ] 文件和网络路径在权限清单中
- [ ] 敏感外发同时声明允许端点与允许敏感类别，交付数据已真实掩码/假名化/分箱
- [ ] 金额、单位、币种、含税/未税口径和显式汇率/税率一致
- [ ] 时间值带中文单位，没有使用带底层单位的旧等待参数
- [ ] 网页记录使用“网页 按字段采集”，记录集合使用“表格处理 把记录整理成表格”
- [ ] SQL 使用 ? 参数
- [ ] 大数据路径是流式或分块的
- [ ] 需求预测没有删除时间点，验证数据没有参与训练阈值拟合
- [ ] XLSX 使用统一摄入/模板接口，没有手工无界读取 ZIP/XML
- [ ] PDF 使用报告/交付接口，表格与 SVG 不是 Markdown 或文件名占位
- [ ] 自动化声明写在 `衡枢.toml`，不是写进 `.代码` 源码
- [ ] 错误路径有 尝试/捕获/最终
- [ ] 已运行 衡枢 检查
- [ ] 正常值、边界值和预期错误路径都有独立测试
- [ ] 测试不依赖执行顺序，资源清理写在每项测试后或测试收尾
